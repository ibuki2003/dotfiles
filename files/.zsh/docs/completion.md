# パス補完の仕様

この文書は、`functions/_mycompleter`、`functions/_my_completion_candidates`、
`functions/_fuzzy_path_prefix` が提供するパス補完の意図をまとめる。
具体的な入出力例と回帰テストは `tests/completion.zsh` を参照する。

## 候補の選択

- パスにスラッシュが含まれていなくても fuzzy path 補完を行う。
  たとえば `Ctoml` から `Cargo.toml` を補完できるようにする。
- 各パス要素では、文字列先頭から一致する prefix match を fuzzy match より優先する。
- prefix match が一件もない場合に限り、そのパス要素を fuzzy match で検索する。
- 最後のパス要素では、完全一致を特別扱いしてほかの prefix match を捨てない。
  たとえば `foo/bar/` と `foo/bar.rs` がある場合、`f/bar` に対して両方を候補にする。
- 中間のパス要素がディレクトリ名に完全一致した場合は、そのディレクトリを優先して探索する。
  同じ prefix を持つ別ディレクトリへ探索範囲を不用意に広げない。
- 複数要素を省略したパスでは、可能な限り深く解決した候補を先に表示する。
  同時に、最初に変換した要素までを展開した候補も残し、段階的に絞り込めるようにする。
- 途中まで解決できたパスの末尾が存在しない場合、未解決の suffix を保持する。
- `~/` と絶対パスでも同じ探索方針を使い、表示上の `~/` は維持する。

## Tab 入力時の挙動

- スラッシュを含まない入力が複数の prefix match を持つ場合、最初の Tab では common prefix
  だけを挿入する。候補の list は表示してよいが、この時点では menu 選択を開始しない。
- 大文字小文字が異なる候補も、小文字入力では大文字小文字を無視した common prefix を小文字で
  挿入する。挿入の前後で候補集合が変わらないことを優先する。
- common prefix を挿入した直後にもう一度 Tab を押したとき、menu 選択を開始する。
- fuzzy match が複数ある場合は common prefix を挿入しない。fuzzy 候補同士の文字列上の
  common prefix は入力の情報量を減らしたり、入力を空にしたりする可能性があるためである。
- 候補が一件だけの場合は、その候補を通常どおり挿入する。
- コマンド名および空の引数では、通常のコマンド・引数補完を優先する。

## 大文字と小文字

- matching は smart case とする。
- 入力が小文字だけの場合は、大文字と小文字を区別しない。
- 入力に大文字が含まれる場合は、大文字と小文字を区別する。
  たとえば `Ctoml` の `C` は大文字として扱い、小文字の `c` だけを含む候補へ
  不用意に fuzzy match させない。

## 変更時の原則

- 上記の方針を変更する場合は、この文書と `tests/completion.zsh` を同時に更新する。
- candidate source の統合を変更する場合は、ネイティブ Zsh と carapace の候補が重複せず、
  同じ操作方針で扱われることを確認する。
- 補完ロジックを変更した後は `make test` を実行する。
