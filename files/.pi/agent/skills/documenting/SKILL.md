# ドキュメント作成

第一に、書きすぎないこと!
わざわざドキュメントに書く必要がある情報とは何か、よく考え、吟味してから書くこと。
{コード, 画面, etc.}を見れば明らか、な情報を書かないように。

学生の書くレポートのようなものが悪い例の代表。
作業内容や、内部の詳しい実装、動作の詳細を説明し、アピールする文書であってはならない。
(詳細な実装の理解にはコードを読む方が正確なので、自然言語での説明は無意味)
使用者の目線に立ち、コードを読まなくてもよいようにする説明、コード読解の補助としての説明、を目指すこと。

コードベースに含まれない情報(目的や意味) を入れるとよい

## README

プロジェクトの地図・入口としての役割を担う。
- プロジェクトを通して達成したい事項、開発の目的
- ディレクトリやファイルの構成、役割
- 実行方法
